Conectar FrontHaTablas con TiendasBackend

FrontHaTablas está hecho para la API de BackTecnophones (MongoDB). TiendasBackend expone una API nueva bajo /api/v1, con otro modelo de datos. Esta guía lista exactamente qué cambiar en el front, archivo por archivo.

Estrategia recomendada: cambiar solo la capa de servicios (src/services/ y src/api/) y que esa capa traduzca entre el formato nuevo y el formato que ya usan las páginas (descripcion, imageId, stockVariante…). Así las páginas no se tocan por ahora y se pueden migrar al modelo nuevo de a poco. En la sección 5 hay funciones de adaptación listas para copiar.

1. Levantar el backend en local

Requisitos: JDK 21 y Docker (PostgreSQL corre en un contenedor que Spring Boot levanta solo).

git clone git@github.com:arielbuchhamer/TiendasBackend.git
cd TiendasBackend
git checkout develop
SPRING_PROFILES_ACTIVE=local ./mvnw spring-boot:run

Con el perfil local la API queda en http://localhost:8080 y:

  • Acepta requests del front en http://localhost:5173 (CORS y cookies ya configurados).
  • Carga un catálogo de ejemplo de HA!Tablas (5 rubros, 10 categorías, 11 productos con variantes e imágenes) si la base está vacía.
  • Crea el usuario del panel admin / admin-local-123.
  • Simula los pagos: el checkout aprueba el pedido al instante (descuenta stock) y redirige a /exito sin pasar por Mercado Pago. Para probar con el sandbox real de MP: MP_SIMULADO=false y credenciales de prueba en .env (ver .env.example).

Para empezar de cero (borra la base local): docker compose down -v y volver a levantar.

2. Configuración del front

Main/.env

VITE_API_URL=http://localhost:8080/api/v1
VITE_FRONT_URL=http://localhost:5173
VITE_USE_MOCKS=false

Los servicios ya arman sus URLs como ${VITE_API_URL}/<recurso>, así que con el prefijo /api/v1 en la variable alcanza para los recursos públicos. Los del panel van bajo /admin (ver sección 3).

src/main.jsx: protección CSRF

Toda request que modifica datos (POST/PUT/PATCH/DELETE), incluido el login, tiene que reenviar la cookie XSRF-TOKEN en el header X-XSRF-TOKEN. Con axios son dos líneas:

axios.defaults.withCredentials = true;   // ya está
axios.defaults.withXSRFToken = true;     // NUEVO: manda X-XSRF-TOKEN también a otro puerto/subdominio

La cookie llega en cualquier respuesta de la API. Antes del primer POST tiene que haber al menos un GET (por ejemplo GET /tienda o el GET /auth/yo que ya hace AuthContext al iniciar). Las instancias de axios creadas con axios.create (authApi.js, LoginService.js) heredan los defaults solo si se crean después; lo más simple es agregarles withXSRFToken: true explícitamente.

Excepciones: POST /checkout (es anónimo) y el webhook de Mercado Pago no requieren el header.

5. Adaptadores listos para copiar

Sugerencia: crear src/services/adaptadores.js y usarlo desde los servicios. Las páginas siguen recibiendo el formato viejo.

// src/services/adaptadores.js
// Traduce entre la API de TiendasBackend y el formato de artículo que usan las páginas.

const sumar = (lista, campo) => lista.reduce((total, x) => total + Number(x[campo] ?? 0), 0);

/** Producto (API nueva) → artículo (formato que usan las páginas). */
export function aArticulo(producto, categoriasPorId = {}, rubrosPorId = {}) {
  const categoria = categoriasPorId[producto.categoriaId];
  const rubro = categoria ? rubrosPorId[categoria.rubroId] : null;
  // Si la única variante no tiene atributos, para las páginas es un artículo "sin variantes"
  const conVariantes = producto.variantes.some((v) => Object.keys(v.atributos ?? {}).length > 0);
  return {
    id: producto.id,
    descripcion: producto.nombre,
    detalle: producto.descripcion,
    precio: Number(producto.precio),
    stock: sumar(producto.variantes, "stock"),
    imageId: producto.imagenes?.[0] ?? null,
    imagenes: producto.imagenes ?? [],
    categoriaId: producto.categoriaId,
    categoriaDescripcion: categoria?.nombre ?? "",
    rubroId: categoria?.rubroId ?? null,
    rubroDescripcion: rubro?.nombre ?? "",
    unidadVenta: producto.unidadVenta,
    activo: producto.activo,
    destacado: producto.destacado,
    version: producto.version,
    // Se guarda la variante por defecto para el carrito de artículos "sin variantes"
    varianteId: producto.variantes[0]?.id ?? null,
    variantes: conVariantes ? producto.variantes.map(aVarianteVieja) : [],
    _producto: producto, // original, por si hace falta
  };
}

function aVarianteVieja(v) {
  return {
    id: v.id,
    sku: v.sku,
    color: v.atributos?.color ?? null,
    atributos: v.atributos ?? {},
    stockVariante: Number(v.stock),
    imageVariante: v.imagenId ?? null,
    precio: v.precio != null ? Number(v.precio) : null,
    activo: v.activo,
    version: v.version,
  };
}

/** Artículo del formulario del panel → body de POST/PUT /admin/productos. */
export function aProducto(articulo) {
  const variantes = articulo.variantes?.length
    ? articulo.variantes.map((v) => ({
        id: v.id ?? null,
        sku: v.sku ?? null,
        atributos: v.color ? { color: v.color } : (v.atributos ?? {}),
        stock: Number(v.stockVariante ?? 0),
        imagenId: v.imageVariante ?? null,
        precio: v.precio ?? null,
        activo: v.activo ?? true,
        version: v.version ?? null,
      }))
    : [{ // artículo simple: una variante sin atributos
        id: articulo.varianteId ?? null,
        atributos: {},
        stock: Number(articulo.stock ?? 0),
        activo: true,
      }];
  return {
    categoriaId: Number(articulo.categoriaId),
    nombre: articulo.descripcion,
    descripcion: articulo.detalle ?? null,
    precio: Number(articulo.precio),
    unidadVenta: articulo.unidadVenta ?? "UNIDAD",
    activo: articulo.activo ?? true,
    destacado: articulo.destacado ?? false,
    imagenes: articulo.imageId ? [articulo.imageId] : [],
    version: articulo.version ?? null,
    variantes,
  };
}

/** Rubro/categoría: nombre ↔ descripcion. */
export const aRubroViejo = (r) => ({ ...r, descripcion: r.nombre });
export const aCategoriaVieja = (c, rubrosPorId = {}) =>
  ({ ...c, descripcion: c.nombre, rubroDescripcion: rubrosPorId[c.rubroId]?.nombre ?? "" });

export const indexarPorId = (lista) => Object.fromEntries(lista.map((x) => [x.id, x]));
Ojo al editar: si el artículo pasó por un adaptador, conservá version, varianteId y el id/version de cada variante hasta el PUT. Sin el id la variante se borra y se crea otra (con otro SKU), y si tiene pedidos la API responde 409.

6. Cambios por archivo de servicio

src/api/authApi.js y src/services/LoginService.js

export const api = axios.create({ baseURL: `${API_URL}/auth`, withCredentials: true, withXSRFToken: true });

export const authApi = {
  me: () => api.get("/yo").then((r) => r.data).catch(() => null),
  login: (username, password) => api.post("/login", { username, password }).then((r) => r.data),
  logout: () => api.post("/logout"),
};

AuthContext no cambia: la respuesta trae id y nombre. Tras 10 intentos fallidos el login devuelve 429 por 15 minutos.

src/services/RubroService.js y CategoriaService.js

  • Mapear las respuestas con aRubroViejo / aCategoriaVieja.
  • getCategoriasByRubro(id) → axios.get(`${URL}`, { params: { rubroId: id } }).
  • getCategoriasConRubro() → pedir categorías y rubros en paralelo y cruzarlos.
  • Crear/editar/borrar → ${API_URL}/admin/categorias, body { nombre, rubroId, orden }.

src/services/ArticuloService.js

  • Cargar una vez (y cachear) categoriasPorId y rubrosPorId para adaptar los productos.
  • getAllArticulos() / getAllArticulosCompletos() → GET /productos?size=100 y mapear data.content con aArticulo (si hay más de 100, recorrer páginas con data.page.totalPages). En el panel usar /admin/productos para ver también los inactivos.
  • getArticulosByRubroId(id) → GET /productos?rubroId=id&size=100.
  • getAllArticulosRandom(limit) → GET /productos/aleatorios?cantidad=limit (lista, no página).
  • getArticuloConRubroYCategoria(id) → GET /productos/{id} + aArticulo (ya incluye nombres de rubro y categoría).
  • crearArticulo / actualizarArticulo → /admin/productos con aProducto(articulo).
  • uploadChangedImages → POST /admin/imagenes con el campo archivos (en vez de files). La respuesta mantiene el orden.
  • attachImageToAccesorio y obtenerUrlsDeImagenes → eliminar; las URLs se arman con el id.
  • URLs de imágenes:
const IMAGENES = `${API_URL}/imagenes`;
getMiniaturaUrl(id) { return `${IMAGENES}/${id}/miniatura`; }
getTarjetaUrl(id)   { return `${IMAGENES}/${id}/tarjeta`; }
getMedianaUrl(id)   { return `${IMAGENES}/${id}/mediana`; }
getImagenUrl(id)    { return `${IMAGENES}/${id}/grande`; }

getImagenUrl antes recibía el id del artículo; ahora recibe el id de la imagen (articulo.imageId). utils/imagenArticulo.js ya pasa imageId, así que no cambia.

src/services/ComprobanteService.js

  • Base ${API_URL}/admin/comprobantes para crear, listar y consultar.
  • getComprobantes() devuelve {content, page}: usar data.content.
  • PDF: axios.get(`${API_URL}/comprobantes/${comprobante.codigo}/pdf`, { responseType: "blob" }) (por codigo, no por id).

7. Carrito y checkout

El carrito tiene que guardar la variante

El checkout nuevo identifica cada línea por varianteId (antes era articuloId + sku). Al agregar al carrito, guardar variant.id si eligió una variante, o articulo.varianteId si es un artículo simple (lo completa aArticulo). Agregar varianteId a normalizeCartItem en store/cartContext.jsx. Los carritos guardados antes en localStorage no lo tienen: conviene vaciarlos (cambiar CART_KEY).

src/models/Venta.js → body de POST /checkout

export function crearPedidoRequest(cliente, address, articulos, conEnvio) {
  return {
    cliente: {
      nombre: cliente.name,
      apellido: cliente.lastname,
      documento: cliente.dni,
      email: cliente.email,
      telefono: cliente.phone,
    },
    entrega: conEnvio ? "DOMICILIO" : "RETIRO",
    direccion: conEnvio ? {
      calle: address.street,
      numero: address.number,
      ciudad: address.city,
      provincia: address.province,
      codigoPostal: address.postalCode,
    } : null,
    // Solo variante y cantidad: precios, envío y total los calcula el servidor
    items: articulos.map((art) => ({ varianteId: art.varianteId, cantidad: art.cantidad })),
  };
}

VentaService.generarVenta

const { data } = await axios.post(`${API_URL}/checkout`, body);
localStorage.removeItem(CART_KEY);
window.location.href = data.checkoutUrl;   // antes la respuesta era directamente la URL
  • El costo de envío lo define el backend (GET /tienda → envio.costoFijo). Mostrar ese valor en el resumen en lugar de calcularlo en el front; si difiere, manda el del servidor (data.total).
  • Errores posibles: 422 con mensaje para mostrar (“No hay stock suficiente de …”, producto no disponible), 400 con errores por campo (email inválido, etc.), 502 si Mercado Pago no responde.
  • La vuelta de Mercado Pago sigue cayendo en /exito, /pendiente y /fallo, con external_reference = código del pedido.

9. Errores

Todas las respuestas de error siguen RFC 9457:

{ "status": 422, "title": "Unprocessable Content", "detail": "No hay stock suficiente de Tabla de asado" }
{ "status": 400, "title": "Bad Request", "detail": "Datos inválidos", "errores": { "cliente.email": "debe ser una dirección de correo electrónico con formato correcto" } }

Donde el front lee err.response.data.message, usar err.response.data.detail (facturacionManual.jsx ya contempla detail).

CódigoCuándo
400Datos inválidos (errores por campo)
401Sin sesión / sesión vencida → ir a /login
403Falta el header CSRF (revisar withXSRFToken)
404No existe (o módulo desactivado)
409Conflicto: versión vieja al editar, o registro en uso al borrar
422Regla de negocio: mostrar detail al usuario
429Demasiados intentos de login
502Falló un servicio externo (Mercado Pago, ARCA)
